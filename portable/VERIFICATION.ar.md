# تحقق إصدار PHP/MySQL الفارغ — 20 أكتوبر 2026

## تحديث النسخ الاحتياطي والنقل

الإصدار `php-mysql-3-backup` يضيف القسم الإداري للنسخة الكاملة المشفرة والاستعادة بمعاينة وتأكيد وكلمة سر، ومفتاح خاص منفصل، وSMTP مع مخزن WebDAV خاص خارج الاستضافة. تاريخ التجهيز والإرسال والفشل منفصل وواضح. لا جدول SQL جديد ولا تغيير للبيانات القائمة. دليل BACKUP.ar.md يشرح الضبط.

نتائج التحديث:820 اختبار JS/TS ناجح، TypeScript بلا أخطاء،83 فحص HTTP/SQL بما فيها استعادة multipart على خادم محلي ثانٍ ثم دخول جديد وفحص الأرصدة، و54 فحصًا إضافيًا للنسخة الكاملة على قاعدتي MySQL. تطابقت كل الجداول المنقولة والصور والحسابات والأرصدة، واختُبر rollback وتلف الملف والمفتاح الخاطئ والإصدار والوجهة والمعاينة وتغيّر إعداد SMTP وانقطاع cron. اختبارات التسليم الخارجي بموصلات اختبار CLI معزولة فقط، وليست إرسالًا لبريد حقيقي أو رصد cron على استضافة حية. أرقام القسم التالي توثّق خط أساس النسخة السابقة، لا أعداد التحديث.

لا توجد بيانات اتصال استضافة أو SMTP/تخزين خارجي حقيقية متاحة في هذا العمل، ولم يُؤكد اسم/رابط الاستضافة الحية. ما فُحص فعليًا هو PHP/MariaDB المحليان وقيود المزود المنشورة. لا نعرض الأسبوعي مفعّلًا في المعاينة أو الحزمة. يلزم ضبط الملف الخاص، اختبار الرفع والقراءة والمنع المجهول، تأكيد رمز وصول البريد، وضبط cron ورصد تشغيله على الاستضافة الفعلية. واجهة الحالة لا تنفذ الجدولة من الصفحة المفتوحة.

## نطاق التسليم

نفس واجهة React/Vite المعتمدة، مع PHP/MySQL بدل مزود البيانات السابق. يبدأ التثبيت الجديد بحساب المدير الذي ينشئه المالك وإعدادات النظام فقط؛ لا مرضى ولا مواعيد ولا جهات اتصال ولا معاملات ولا خدمات أو أدوية أو معامل تجريبية. قيمة الكشف الأولية100 جنيه قابلة للتعديل، وليست دفعة محصلة تلقائيًا.

حُذفت مكتبات Firebase وملفات تشغيله وقواعده ومساراته البديلة وأدوات تصدير/نقل البيانات القديمة من مصدر هذا الإصدار. لا حاجة لأي حساب Firebase لتشغيله. لم تُقرأ أو تُعدّل أو تُحذف بيانات المشروع السحابي الأصلي. توجد نقطة رجوع محلية للمصدر وملفات الإنتاج قبل التنظيف، ويبقى تاريخ GitHub السابق متاحًا.

المثبت يرفض قاعدة تحتوي سجلات تشغيل أو حسابًا أو علامة تثبيت سابقة، ولا يمسحها. يحتفظ بعلامة دائمة ويعيد410 عند محاولة فتحه ثانية، حتى لو أُزيلت الحسابات يدويًا. لا بيانات اعتماد افتراضية. SQL لإنشاء الجداول فقط.

## نتائج الاختبار

- **817 اختبار JavaScript/TypeScript ناجح، صفر فشل أو تخطٍّ**. تشمل منطق المرضى والأسنان والروشتة والاتصالات والأسعار والمواعيد والصلاحيات والحسابات والنسخ والواجهة. أُزيلت اختبارات المزود السحابي الذي حُذف؛ هذا العدد هو الاختبارات المحتفظ بها، وليس مقارنة تغطية رقمية مع الإصدار السابق. فحص TypeScript `tsc --noEmit` بلا أخطاء.
- **61 فحص HTTP/SQL ناجحًا** على PHP8.4.26 وMariaDB11.4.8، في قواعد loopback منعزلة وبيانات مصطنعة فقط. تحققت أوامر SQL من خلو جميع جداول التشغيل عند التثبيت، ووجود مالك واحد وأربعة سجلات إعداد فنية فقط.
- تثبيت المالك وإقفال المثبت؛ الدخول الصحيح والخاطئ وتذكر الجلسة والخروج والإبطال وإعادة التعيين لمرة واحدة. سجل النشاط يعرض اسم الفاعل، ولا يعرض كلمة سر أو تجزئتها.
- حفظ المريض وتسلسل رقم الملف، أرقام عربية مستوردة من جدول مستقبلًا، حفظ الخدمة والأسنان والكشف والتحصيل الجزئي، منع تجاوز المتبقي. الطلب الجديد يسترجع ما حُفظ من SQL.
- نفس معرّف المحاولة لا يكرر الدفعة؛ تعارض إصدار البيانات يرفض التعديل القديم. التحقق من المحاولة غير المؤكدة والإلغاء يمنعان تكرار عملية مالية عند فقد الرد.
- تسجيل التركيبة والجلسة وتحصيل المريض في معاملة واحدة، مع فصل تكلفة المعمل عن سعر البيع، مسار المعمل الافتراضي وأسعاره الخاصة، ودفعات المعمل وتوزيعها.
- تعارض المواعيد، مطابقة وتكرار أرقام جهات الاتصال، المصروف المدفوع فعليًا ودفعة المورد اللاحقة دون تكرار المصروف، وربط الخامات وتكلفة الاستهلاك.
- رفع PNG مصطنعة وفحص نوعها وحجمها، ومنع الوصول للفاتورة دون مصادقة. سكرتيرة لا تستطيع الاستيراد أو النسخ/التصدير، ولا يصل لجهازها ثمن المعمل دون الصلاحية. حجب القيم المالية المتداخلة ومنع التحصيل عند سحب الصلاحية. رفض الدخول خارج أيام العمل وحماية Origin/CSRF.
- نسخة JSON من **نظام PHP نفسه** تستعيد السجلات والصور إلى تشغيل فارغ، دون نسخ الحسابات أو كلمات السر. تكرار نفس النسخة لا يكرر الصفوف، وتُرفض صيغة النسخة القديمة. هذا نسخ احتياطي مستقبلي، وليس أداة نقل Firebase.
- **11 فحص PHP أساسي ناجحًا** للتقويم والدوام العابر لمنتصف الليل والأرقام العربية وحساب القروش والتقريب. جميع ملفات PHP النهائية اجتازت فحص الصياغة.
- اختبار خلو بيانات الحسابات والمخزون والمرضى من NaN/Infinity وعرض صفر صحيح. لا توجد سجلات مصطنعة ضمن إعدادات الإنتاج؛ عينات الاختبارات موجودة في ملفات الاختبار فقط ولا تُستورد عند التشغيل.
- مراجعة أقسام الرئيسية والمرضى وجهات الاتصال والمواعيد والتركيبات والماليات والإعدادات، وأقسام الإعدادات الداخلية، في متصفح على1440×900 و390×844. قورنت صور قبل/بعد. فُحصت قوائم المزيد ونوافذ إضافة أول مريض/مصروف دون حفظ بيانات في قاعدة المعاينة الفارغة. لم يظهر تجاوز أفقي في الشاشات المحمولة المفحوصة؛ Refresh احتفظ بالجلسة والبيانات في الفحص المحلي. لم تُرسل رسائل أو تُجرَ اتصالات حقيقية.

تشغيل اختبارات API للمطور عبر `node scripts/test-portable-api.mjs` يتطلب بيئة PHP/MariaDB المحلية المنعزلة المحددة في السكربت، ولا يتصل باستضافة حية. تفاصيل الأحجام والمراجعة البصرية في DESIGN-REVIEW.ar.md.

## حدود التحقق وما يحتاج المالك

1. **لم يُنشر هذا الإصدار على استضافة المستخدم.** الحزم جاهزة للرفع اليدوي؛ أنشئ قاعدة فارغة، اضبط الملف الخاص وHTTPS، ثم أنشئ المدير بنفسك حسب INSTALL.ar.md. لا ترسل كلمات السر أو ملف الاتصال.
2. خادم PHP المحلي لا يطبّق قواعد Apache `.htaccess`. يجب على الاستضافة التأكد من منع الوصول إلى الملفات الخاصة، ومن عمل Refresh على الصفحات، ورفع صورة اختبار وصلاحيات المستخدمين قبل إدخال بيانات حقيقية.
3. مقاس الجوال في المتصفح ليس جهاز iPhone/Safari فعليًا. لم تُختبر مشاركة صورة الروشتة إلى تطبيق واتساب حي أو طابعة حقيقية. محاولة المقارنة البصرية الإضافية لملف مريض مصطنع مملوء لم تكتمل بسبب تقييد أداة المتصفح؛ لم أتحايل عليه. اختبارات API ومنطق الملف والروشتة ناجحة، لكن هذا لا يغني عن مراجعة المالك على جهازه.
4. آخر تحسينات تسمية سجل النشاط وقيم المعاينة الصفرية وإدارة التركيز في نافذتي المريض والمصروف اجتازت التجميع والاختبارات؛ بعض الصور محفوظة قبل هذه اللمسات الأخيرة. لا أدّعي إجراء دورة متصفح كاملة جديدة بعد آخر تعديل.
5. InfinityFree المجانية تمنع cron واستقبال Webhooks/الطلبات الآلية. تبقى القوالب وفتح واتساب والمشاركة اليدوية، ولا يوجد وعد بإرسال تلقائي بالخلفية. المزامنة قراءة كل دقيقة أثناء فتح الصفحة فقط، وليست WebSocket أو حفظًا أوفلاين.
6. موصل تحليل الفواتير بالذكاء الاصطناعي مغلق افتراضيًا. لم يُختبر بمفتاح حي، ولم تُرسل بيانات مرضى خارجيًا. تفعيله يحتاج مزودًا وإمكانات الاستضافة والموافقة على إرسال الصورة؛ لا يُعرض نجاح وهمي عند تعطيله.
7. لم يُنفّذ اختبار اختراق مستقل أو حمل كبير أو Lighthouse/قياس شبكة هاتف حقيقي. راقب حجم قاعدة البيانات ورفع الصور وحدود الخطة، وخذ نسخ SQL خاصة منتظمة.

لا تغيير لمخطط SQL مقارنة بالإصدار PHP السابق (schemaVersion1). لا تعِد استيراد schema.sql على قاعدة تشغيل قائمة لمجرد تحديث الواجهة. النسخة المحلية القديمة4173 لم تُحذف أو تُوقف، ولا توجد أي عملية نشر/حذف سحابي ضمن هذا التسليم.

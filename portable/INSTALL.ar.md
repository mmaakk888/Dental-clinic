# دليل تثبيت العيادة الفارغة — PHP/MySQL

## الحزم والمتطلبات

- clinic-htdocs.zip: ملفات الإنتاج العامة فقط؛ لا يحتاج Node.js على الاستضافة.
- clinic-sql-and-tools.zip: schema.sql وقوالب الاتصال والإعدادات وأداة استرجاع كلمة السر للطوارئ. ليست للرفع العام.
- clinic-source.zip: المصدر الحالي للتطوير. أدوات نقل البيانات القديمة أُزيلت، ولا حاجة لتصدير Firebase أو حساباته.
- يلزم PHP 8.2+ مع PDO وpdo_mysql، MySQL 5.7+ أو MariaDB 10.4+، InnoDB وutf8mb4، Apache مع .htaccess وmod_rewrite، وHTTPS. تحليل الفواتير الاختياري يحتاج curl ومفتاح مزود وموافقتك على إرسال الصورة، وهو مغلق افتراضيًا.

## 1. الدومين وHTTPS

أنشئ الدومين أو الفرعي، وحدد جذر الموقع الصحيح: public_html في cPanel أو htdocs في InfinityFree غالبًا. فعّل SSL من SSL/TLS Status → AutoSSL إن أتاحه المزود، أو أداة Free SSL Certificates في InfinityFree. أكمل التحقق والتثبيت، وافتح الرابط عبر HTTPS دون تحذير قبل تسجيل الدخول. اختر رابطًا ثابتًا مع www أو بدونه، وحوّل HTTP والاسم البديل إليه من لوحة الاستضافة.

[دليل SSL في InfinityFree](https://forum.infinityfree.com/t/how-to-get-free-ssl-https-on-infinityfree/49323).

## 2. قاعدة جديدة فارغة

1. افتح MySQL Database Wizard / Manage My Databases في اللوحة.
2. أنشئ قاعدة فارغة ومستخدمًا منفصلًا وكلمة سر قوية، واربط المستخدم بالقاعدة.
3. احفظ اسم القاعدة والمستخدم كاملين بالبادئة. في InfinityFree استعمل MySQL Hostname المعروض، لا تفترض localhost.
4. افتح phpMyAdmin، اختر القاعدة الجديدة، ثم Import لملف schema.sql فقط. المخطط لا يحتوي INSERT لمرضى أو مستخدمين أو معاملات، ولا أوامر حذف.
5. التشغيل اليومي يحتاج SELECT/INSERT/UPDATE/DELETE؛ إنشاء الجداول يحتاج صلاحيات الإنشاء وقت التثبيت فقط. لا تستعمل root للتشغيل.

لا تمسح قاعدة قديمة. إذا وجد المُثبّت حسابًا أو سجلات تشغيل أو علامة تثبيت سابقة يرفض إعادة التهيئة، ولا يحذفها. اختر قاعدة جديدة بدل تجاوز الحماية.

[معالج قواعد cPanel](https://docs.cpanel.net/cpanel/databases/mysql-database-wizard/).

## 3. ملفات الموقع والاتصال

1. فك clinic-htdocs.zip مباشرة داخل جذر الدومين، بحيث index.html وassets وapi بجانبه، وليس داخل مجلد htdocs إضافي.
2. أظهر الملفات المخفية وتأكد من رفع .htaccess العام وapi/.htaccess. لا ترفع ZIP المصدر أو ملفات SQL أو النسخ الاحتياطية.
3. خارج جذر الدومين أنشئ clinic-private بجانب htdocs أو public_html. انسخ إليه config.example.php باسم config.php وdefaults.json وملف الحماية من حزمة SQL.
4. عدّل app_url إلى رابط HTTPS المختار، ثم database.host/name/user/password/port حسب اللوحة. لا تكتبها في JavaScript.
5. ولّد قيمتين عشوائيتين مستقلتين لـ app_key وinstall_token، كل منهما64 خانة hexadecimal. على لاب فيه PHP شغّل الأمر التالي مرتين:

```powershell
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

لا تستعمل كلمة سر حسابك بدل المفتاح. اترك allow_http_loopback=false في الاستضافة، وصلاحيات الملفات600 أو640 بحسب الخادم؛ لا777. لا ترسل ملف الاتصال في المحادثة أو GitHub.

إذا منعت الاستضافة الملفات خارج الجذر: ضع config.php وdefaults.json داخل htdocs/_private مع .htaccess الخاص. افتح رابط /_private/defaults.json بنفسك؛ يجب403 أو404. إذا ظهرت محتوياته فلا تبدأ العمل حتى إصلاح حماية الخادم. لا تضع SQL أو نسخًا احتياطية في هذا البديل.

## 4. إنشاء المدير وإغلاق المُثبّت

1. افتح https://YOUR-DOMAIN/install.html بعد ضبط SSL والاتصال.
2. اكتب install_token الخاص، واسم المدير واسم الدخول وبريده إن أردت، وكلمة سر جديدة وتأكيدها. لا توجد كلمة سر أو مستخدم افتراضي.
3. بعد النجاح تُنشأ إعدادات النظام وحساب المدير فقط. تبقى السجلات التشغيلية والفهارس فارغة، وتعرض الإحصاءات صفرًا. قيمة الكشف الأولية100 جنيه، ولا تُسجل أو تُحصّل بمجرد فتح ملف.
4. يحتفظ السيرفر بعلامة تثبيت دائمة، ويمنع إعادة المُثبّت حتى لو حُذفت الحسابات يدويًا. الواجهة تقفل زر الإنشاء أيضًا. احذف قيمة install_token من config.php بعد النجاح، ويمكنك حذف install.html من الاستضافة كإجراء إضافي؛ لا تحذف setup.js أو reset.html اللازمين لاسترجاع الحساب.
5. افتح العيادة وسجّل الدخول. اضبط الهوية والخدمات والأسعار والأدوية والمعامل الافتراضية من الإعدادات، ثم أضف أول مريض. لا تشارك حساب المدير مع السكرتيرة؛ أنشئ لها حسابًا مستقلًا بصلاحيات محدودة.

كلمات السر تُجزّأ بـ bcrypt، والجلسات محفوظة مجزّأة في SQL مع Cookie HttpOnly/Secure/SameSite، وCSRF والتحقق من الأدوار وأوقات العمل من السيرفر. تعديل الحساب يلغي جلساته السابقة. «تذكرني» لا يلغي قيود الحساب.

## 5. أول مراجعة قبل الاستخدام الحقيقي

افتح الأقسام السبعة على الكمبيوتر والهاتف وتأكد أن القوائم فارغة والمبالغ0. جرّب في قاعدة اختبار منفصلة: مريض وخدمة ودفعة جزئية ومتأخر، موعد، معمل وتركيبة، مصروف وصورة. نفّذ Refresh وافتح من جهاز آخر. اختبر حساب السكرتيرة ومنع الاستيراد والتصدير وتكلفة المعمل وأوقات العمل. لا تستخدم ملف مريض حقيقي للاختبار.

الصور PNG/JPEG/WebP تُحفظ محمية في MySQL؛ صور الفواتير تستهدف150KiB ولا تُرفع الأصول تلقائيًا. رابط الفاتورة يتطلب مصادقة وصلاحية. الشعار العام فقط متاح لصفحة الدخول. الاستضافة الفعلية وSafari ومشاركة واتساب تحتاج اختبارًا لديك؛ الفحص المحلي ليس بديلًا عنها.

## 6. النسخ الاحتياطي واسترجاع حساب المدير

نزّل نسخة SQL كاملة دوريًا من phpMyAdmin واحفظها مشفرة خارج الموقع، ومعها config.php منفصلًا. JSON النظام نسخة تشغيلية للمرضى والإيصالات والصور والإعدادات دون كلمات السر؛ ليس بديلًا عن SQL للحسابات والجداول الفنية. استعادة JSON محصورة بنسخ هذا الإصدار وإلى تشغيل فارغ، ولا تستبدل بيانات قائمة. للنسخ الكبيرة استخدم SQL من phpMyAdmin، لا يوجد محول Firebase في هذا الإصدار.

نسيان كلمة سر المدير: لا تفتح المُثبّت من جديد ولا تعدّل كلمة السر نصيًا في SQL. اعرف UID من جدول dc_users في phpMyAdmin، ثم على اللاب شغّل أداة الطوارئ الخاصة:

```powershell
php portable/tools/reset-password.php --user=OWNER_UID --url=https://YOUR-DOMAIN --output=owner-reset.private.sql
```

استورد الملف الخاص عبر phpMyAdmin، وافتح الرابط الذي طبعته الأداة بنفسك وحدد كلمة السر. الرابط صالح ساعة ولمرة واحدة، وإعادة التعيين تلغي الجلسات. لا ترفع الأداة أو SQL للدومين ولا ترسل الرابط في المحادثة. بعد الدخول يمكن إنشاء روابط إعادة تعيين للمستخدمين من الإعدادات.

## 7. قيود الاستضافة والوظائف الاختيارية

التحديث بين الأجهزة قراءة خفيفة كل دقيقة أثناء فتح الصفحة، مع تنزيل السجلات عند تغيّر إصدارها فقط؛ لا WebSocket ولا حفظ أوفلاين صامت. فتح واتساب والقوالب وصورة الروشتة يدويًا يبقى كما هو، ولا يعني فتح واتساب وصول الرسالة.

InfinityFree المجانية لا تصلح لاستقبال Webhooks/بوت واتساب بسبب فحص المتصفح، وcron غير متاح. لا تعتمد على مؤقت داخل الصفحة لإرسال تذكير والموقع مغلق، ولا على cron خارجي يتجاوز الحماية. اختر مزود PHP يدعم الطلبات الآلية وcron إن احتجت الأتمتة؛ الكود لا يُعرض كأنه يرسل آليًا. هذه القيود تخص المزود، لا كل cPanel.

[فحص المتصفح والطلبات الآلية](https://forum.infinityfree.com/t/browser-security-system-features-and-limitations/49353)، [تعطيل cron](https://forum.infinityfree.com/t/cron-job-feature-is-now-disabled/80495).

AI اختياري مغلق، ومفتاحه داخل config.php فقط، ويتطلب curl وخروجHTTPS وموافقة صريحة لإرسال البيانات. لم يُفعّل مزود مدفوع أو تُرسل بيانات مرضى أثناء الفحص. راقب حدود حجم MySQL/رفع الصور/الاستيراد في خطة الاستضافة ولا تفترض مساحة غير محدودة.

## 8. التحديث والرجوع والنقل

قبل تحديث البرنامج خذ SQL ونسخة ملفات الإصدار العامل. على اللاب pnpm install --frozen-lockfile ثم pnpm lint وpnpm test ثم pnpm build. انقل مجلدي build/portable-release وbuild/portable-artifacts السابقين إلى اسم آخر إن وُجدا؛ لا يُستبدلان تلقائيًا.

ارفع ملفات htdocs الجديدة فقط، assets أولًا ثم index.html. لا تعِد استيراد schema.sql أو إعداد المدير في تحديث تصميم عادي، ولا تستبدل config.php. يمكن الرجوع لملفات الإصدار المتوافق مع نفس schema دون إرجاع SQL قديم وإضاعة المعاملات الأحدث. أي تغيير مستقبلي للمخطط يحتاج ترحيلًا متوافقًا مدروسًا.

لنقل الاستضافة: صدّر SQL كاملًا، استورده في قاعدة جديدة، وانقل ملفات الموقع والاتصال الخاص، وعدّل app_url وبيانات MySQL وفعّل SSL. لا ارتباط بمزود قاعدة خارجي. بيانات Firebase القديمة لم تُمس وليست مصدر بيانات هذه النسخة.

## 9. التطوير المحلي

PHP CLI 8.2+ وpdo_mysql وقاعدة محلية منفصلة. ضع config.php وdefaults.json في مجلد خاص، واجعل app_url=http://127.0.0.1:5173 للتطوير، أو4174 لمعاينة الإنتاج، مع allow_http_loopback=true محليًا فقط. ثم:

```powershell
$env:CLINIC_LOCAL_CONFIG='C:\clinic-private\config.php'
$env:CLINIC_PHP_BINARY='C:\php\php.exe'
pnpm dev
```

عدّل المسارين. pnpm preview يشغّل حزمة الإنتاج بعد البناء على4174؛ التطوير على5173 وخلفه PHP على4187، جميعهاloopback. لا يحتاج خادم الاستضافة هذه الأدوات. المعاينة القديمة4173 وبيانات متصفحها لم تُحذف تلقائيًا؛ لم يعد لها أمر تشغيل أو مسار Firebase في المصدر الجديد.

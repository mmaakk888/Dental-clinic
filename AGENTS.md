# Dental clinic — PHP/MySQL

## Authoritative scope (20 October 2026)
The owner requested a fresh, empty PHP/MySQL installation. No old cloud/browser data migration. Never change, delete or deploy the original cloud resources. The new installer creates exactly one owner; no default password, demo patients, transactions or accounts. Service/drug/lab catalogues start empty and the configured optional examination fee is 100 EGP.

Preserve the established React/Vite/Tailwind interface, colours, floating bottom navigation, screen order, mobile More behaviour and action locations. Refine spacing, readability, RTL and interaction without replacing the design. No duplicate top navigation. Respect reduced motion; do not delay saving or navigation for animation. Keep one canonical prescription document for print and PNG.

Use existing libraries first. Production is Apache/PHP 8.2+ and MySQL/InnoDB/utf8mb4. No hosted Node, browser medical-data persistence or external database SDK. Settings and clinical records belong to SQL, secrets only in the private config outside htdocs. Never ship local config, backups, credentials or real patient records in GitHub or ZIPs.

PHP enforces roles, schedule, CSRF, session revocation and invoice access. Secretary cannot import/export/back up users or patient data. Prices and actual receipts are distinct; examination toggle does not imply payment. Prosthetic order, patient debt and lab case remain one transaction. Supplier costs are private. Retain exact operation IDs on uncertain replies; never repeat a payment under a new ID without a resolved previous attempt.

Build via pnpm build; only build/portable-release/htdocs is public. SQL/config/recovery instructions are separate. Installer must remain permanently closed after success even if accounts are manually removed. No automatic reset, database DROP/TRUNCATE or deployment. Test on fabricated loopback databases only; do not use real accounts for visual QA. Run TypeScript, retained business/UI tests, PHP lint, actual PHP/MySQL API tests and responsive browser checks. Report verification boundaries honestly.

The pre-refinement source/public ZIPs and screenshots are retained under the ignored .clinic-local/ui-refinement-20261020 and review-proofs/ui-20261020. The original 4173 preview and its data must not be erased or stopped as an incidental cleanup. Release archives are immutable: rename a prior release before generating a new one.

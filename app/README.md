# نظام إدارة عيادة الأسنان — PHP/MySQL

واجهة عربية React/Vite بنفس التصميم المعتمد، بقاعدة MySQL وجلسات وصلاحيات PHP من السيرفر. تعمل على استضافة PHP مشتركة، دون Node.js أو اعتماد على مزود قاعدة خارجي.

## البداية

ابدأ من [دليل التثبيت](portable/INSTALL.ar.md). تستورد مخطط الجداول فقط، وتضبط الاتصال خارج htdocs، ثم تنشئ حساب المدير بنفسك من المُثبّت. يبدأ المرضى والمواعيد وجهات الاتصال والمعامل والمصروفات والخامات وفهارس الخدمات والأدوية فارغة. لا حساب/كلمة سر افتراضية ولا نقل بيانات قديمة.

**لم تثبّت النظام بعد؟** استخدم الحزمة الكاملة `clinic-complete-php-mysql-10-rx-workflow.zip` مباشرة، وليس سلسلة حزم تحديث. تحتوي `htdocs/` و`private/` وZIP المصدر ودليلًا مختصرًا وبصمات الملفات؛ ارفع محتويات `htdocs/` فقط إلى جذر الدومين. التفاصيل في [ابدأ من هنا](portable/FIRST-INSTALL.ar.md). ينتج `pnpm build` الحزمة الكاملة والملفات المنفصلة معًا من المصدر الحالي، دون بيانات المعاينة أو أسرار الاستضافة.

للمتابعة من حساب أو جهاز آخر، ابدأ بـ[خطوات الاستكمال والرسالة الجاهزة](CONTINUE-HERE.ar.md)، ثم [سجل القرارات والخطوات](PROJECT-HISTORY.ar.md) و[تسليم المشروع](HANDOFF.ar.md) وAGENTS.md. تحفظ هذه الملفات سياق العمل والمرجع المعتمد والتشغيل والاختبارات وحدود نشر الأسرار؛ ليست نسخة حرفية للمحادثة أو نسخة لقاعدة البيانات. يجب تحديثها بعد كل دورة عمل مهمة.

## الإصدار الحالي — v10

`php-mysql-10-rx-workflow`: محرر إداري محفوظ لتصميم الروشتة بنفس ورقة الطباعة والصورة، وتضمين الشعار المحمي في PNG دون طلبات خارجية، وترقيم زمني موحّد للجلسات وسجل تحصيلات واضح، وتحسين تنظيم واتساب وحماية مسوداته. يحتفظ بإصلاحات v9 كلها وبنفس الهوية ومخطط SQL. للتثبيت الجديد استخدم الحزمة الكاملة؛ ولنسخة مثبّتة v4–v9 فقط حزمة `clinic-update-v4-v5-v6-v7-v8-v9-to-v10.zip`. لا تعِد التثبيت أو استيراد SQL فوق قاعدة موجودة. راجع [دليل الروشتة والجلسات](portable/RX-WORKFLOW.ar.md) و[المراجعة التفصيلية](portable/RELEASE-REVIEW.ar.md).

## التطوير والبناء

```powershell
pnpm install --frozen-lockfile
pnpm lint
pnpm test
pnpm build
```

النتيجة في build/portable-artifacts: حزمة htdocs، وحزمة SQL/إعدادات خاصة/أداة استرجاع كلمة السر، والمصدر الحالي. لا ترفع المصدر أو SQL إلى مجلد الدومين. الإصدار السابق لا يُستبدل بصمت.

المعاينة: PHP CLI 8.2+ مع pdo_mysql وقاعدة محلية منفصلة وملف اتصال خاص. اضبط CLINIC_LOCAL_CONFIG وCLINIC_PHP_BINARY عند الحاجة، ثم pnpm dev على5173، أو pnpm preview على4174 بعد البناء. لا تُنشأ بيانات تلقائيًا. التفاصيل بالدليل.

## التحقق والأمان

من «زيارة بدون موعد» يمكن اختيار [زيارة بدون ملف](portable/UNFILED-VISITS.ar.md): يُحفظ الزائر بجهات الاتصال والخدمة والإيصالات في الحسابات، دون استهلاك رقم ملف. الزيارات والأرصدة قابلة للمراجعة والتحصيل من جهات الاتصال، ومشمولة بالنسخ والاستعادة، وليست ضمن قائمة الملفات المرقمة.

قسم [النسخ الاحتياطي والنقل](portable/BACKUP.ar.md): نسخة كاملة مشفرة، مفتاح فك منفصل لدى المالك، فحص ومعاينة قبل الاستعادة إلى اتصال الاستضافة الجديدة، وإرسال خارجي عبر SMTP/WebDAV. الأسبوعي غير مفعل حتى اختبار البريد ورصد cron؛ لا يعتمد على مستخدم فاتح الصفحة.

راجع [نتائج الاختبار](portable/VERIFICATION.ar.md) و[المراجعة البصرية والأداء](portable/DESIGN-REVIEW.ar.md). الصلاحيات والحسابات المالية تُفرض في PHP؛ لا يُعد إخفاء زر حمايةً للبيانات. النسخ الاحتياطية المستقبلية من النظام وSQL تبقى خاصة. لا اتصال بالمشروع السحابي القديم أو تعديل بياناته.

قسم [تحديث النظام](portable/UPDATE.ar.md) للمدير: حزمة ZIP موقّعة، فحص توافق ومعاينة، نسخة رجوع مشفرة خاصة، صيانة تمنع الحفظ، تحديث الكود وترحيلات وصفية آمنة، وفحص تشغيل بالإصدار الجديد قبل النجاح. استعادة مستقلة عند الفشل وبديل يدوي للاستضافات المقيدة. لا استضافة محددة أو نشر حي ضمن هذا الإصدار. `pnpm test:updates` يختبر النجاح والفشل على قاعدة محلية مملوءة مصطنعة؛ `pnpm package:update` يعد الحزم المستقبلية دون وضع مفتاح التوقيع الخاص في المصدر أو الاستضافة.
## تنظيم المستودع

على GitHub: التطبيق المعتمد داخل `app/` في فرع `main`، والأرشيف غير التشغيلي داخل `archive/`. ادخل `app` قبل أوامر التطوير. ZIP المصدر المستقل ومجلد المعاينة المحلي `preview` هما جذر التطبيق مباشرة. الأدلة والاختبارات وأدوات الإنقاذ لازمة للمشروع وتبقى معه؛ الملفات الخاصة المحلية لا تُرفع.

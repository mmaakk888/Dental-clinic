# مراجعة الإعدادات والتمرير وتنظيم المشروع — v9

الإصدار `php-mysql-9-settings-scroll`، مع نفس الهوية والألوان وتقسيم الشاشات. لا تغيير في مخطط SQL ولا في أرصدة التشغيل أو تاريخ الأسعار. لا نشر حي أو إرسال رسائل أو تعديل موارد سحابية.

## الإصلاحات العملية

1. **تمرير حجز الموعد:** كان fieldset نفسه يملك overflow؛ ظهر scrollHeight أكبر من ارتفاعه لكن ظل scrollTop صفرًا بعد محاولة التمرير. نُقل التمرير إلى div مستقل، وبقي fieldset لتعطيل الحقول أثناء الحفظ فقط. ظهرت الحقول الأخيرة مع بقاء أزرار التأكيد والإغلاق متاحة. في العرض القصير تتمرر النافذة كاملة بدل حبس الأزرار. يوجد أيضًا مسار تمرير احتياطي للنوافذ المؤطرة، وفحص بنيوي يمنع إعادة المشكلة إلى أي fieldset في المشروع.
2. **مسودات الإعدادات:** يحتفظ واتساب ومسار توزيع التركيبات بمسوداتهما عند تغيير تبويبات الإعدادات. مغادرة القسم الرئيسي أو Refresh تحذر عند وجود تعديل حقيقي؛ مجرد اختيار مستلم أو الضغط على نفس القسم لا ينشئ تحذيرًا زائفًا.
3. **مكتبة واتساب:** دمج مستقل لتحديثات القوالب، وإيقاف الحفظ عند تعديل نفس القالب من جلستين، دون فقد المسودة. الرسائل الفعلية تستخدم النص المحفوظ، لا قالبًا لم يُحفظ. الحملات تحفظ مسودتها، وموافقاتها منفصلة عن حفظ النصوص. تظهر «الأرقام» والهوية «بدون ملف» بدل معرّف داخلي مضلل.
4. **العرض المحمول لواتساب:** تقسيم واضح لخمس وظائف، مع إخفاء أدوات اختيار القالب عندما يكون الاختيار مطويًا؛ إصلاح محدد CSS الذي لم يكن يطابق العناصر داخل fieldset. الصور لا تُرسل تلقائيًا؛ الفتح والمشاركة لا يثبتان الإرسال أو التسليم.
5. **التسعير:** يمكن حفظ رسوم الكشف حتى مع فهرس خدمات فارغ تمامًا. أُضيف بحث في أسعار التركيبات، وترتيب متجاوب للتبويبات، ونص يفرّق إضافة الكشف للمطلوب عن تسجيل التحصيل. لا أسعار افتراضية مختلقة، ولا إعادة تسعير لجلسة أو حالة قديمة.
6. **التحقق من السيرفر:** رفض قوائم الخدمات المشوهة والأسماء المتكررة والأسعار غير الرقمية أو السالبة أو الأكبر من الحد، وحذف أنواع التركيبات التاريخية. فحص نوع وطول قوالب واتساب وأرقام وحالات الموافقة، ورفض مفاتيح API في المتصفح أو تفعيل أتمتة غير موجودة. الحماية ليست اعتمادًا على تعطيل زر فقط.

## الفحص الآلي

اختبارات JS/TS، وفحص TypeScript وصياغة PHP، وفحص HTTP/SQL على قاعدة اختبار مصطنعة مستقلة، واختبارات النسخ والاستعادة والتحديث والرجوع. تتضمن رحلة المريض من الملف/الزيارة بدون ملف، الخدمة والأسنان والكشف والتحصيل الجزئي، المواعيد وتعارضها، الروشتات، إنشاء التركيبة وربطها بمعمل وسعره، الدفعات المؤرخة والمجمعة، المصروف والمخزون، الأدوار والخصوصية، ثم الاستعادة إلى قاعدة ثانية ومطابقة المرفقات والأرصدة. تفاصيل النتائج النهائية وأعدادها في VERIFICATION.ar.md.

## GitHub والملفات

- `app/`: مصدر التطبيق الحالي وحده، مع الاختبارات والأدلة وأدوات البناء والإنقاذ اللازمة. ابدأ pnpm من هذا المجلد عند تنزيل المستودع. ZIP المصدر المستقل يبدأ من جذر التطبيق مباشرة، ومجلد preview الموجود على اللاب هو جذر التطبيق أصلًا.
- `archive/`: مرجع واضح للمواد القديمة، مع وصف بيئة الإنشاء القديم الذي لا يستخدمه التطبيق. النسخة السابقة الكاملة محفوظة برابط commit ثابت وتاريخ Git، بدل تكرار كود وإعدادات قديمة داخل التطبيق الحالي.
- الملفات الخاصة المحلية والإعدادات والمفاتيح والنسخ والصور الاختبارية لا تُرفع إلى GitHub. لم تُحذف بيانات المعاينة أو النسخ الخاصة كجزء من تنظيف المصدر.

## حدود يجب عدم إخفائها

لم تُختبر الاستضافة الفعلية أو Apache/HTTPS أو بريد/cron أو WhatsApp API حي أو مشاركة صورة عبر Safari/الطابعة. فحص المقاسات بالمستعرض ليس اختبار جهاز iPhone فعلي. منع المتصفح فتح ملف المريض الاختباري في الدورة السابقة ما زال حدًا للمراجعة البصرية؛ لم يُتجاوز، بينما اختبارات منطق الملف وAPI ناجحة. جرد كل النوافذ واختبارات المنطق لا يعني أن كل نافذة اختُبرت يدويًا بكل حالات بياناتها. الفحص ليس اختبار اختراق أو حمل مستقل، ولا ضمانًا بانعدام كل العيوب.

# النسخ الاحتياطي والنقل — شرح مختصر

من لوحة التحكم افتح «النسخ الاحتياطي والنقل». القسم وواجهة PHP متاحان للمدير/الطبيب المصرح له فقط؛ السكرتيرة لا تستطيع تنزيل نسخة أو استعادتها حتى باستدعاء الرابط مباشرة. يلزم تأكيد كلمة سر المدير مع العمليات الحساسة.

## نسخة يدوية كاملة الآن

1. فعّل sodium وzlib في PHP. من القسم اضغط «تنزيل مفتاح جديد منفصل». ينشأ المفتاح في ذاكرة PHP ويُرسل لجهازك فقط، عبر HTTPS (أو loopback المحلي)، ولا يُحفظ المفتاح الخاص على الخادم. احفظ الملف في وسيط منفصل وآمن، ولا ترسله مع النسخة بالبريد. احتفظ بالمفاتيح القديمة عند تدوير المفتاح.
2. أكد أنك حفظته، ثم «حفظ الإعدادات». الخادم يحفظ المفتاح العام فقط. لا يوجد مفتاح افتراضي في حزمة الموقع.
3. اضغط «تحميل نسخة كاملة» واحفظ ملف `.clinicbackup` خارج الاستضافة. الملف gzip ثم تشفير sodium sealed-box مصادق (X25519/XSalsa20-Poly1305)؛ تلفه أو المفتاح غير المطابق يمنع فتحه. يمكن تنزيله دون إعداد البريد أو cron.

تشمل النسخة جميع جداول التشغيل والأرشيف والإعدادات والحسابات بتجزئات كلمات سرها، سجل العمليات والنشاط، وكل محتوى dc_files (الصور والمرفقات) مع بصماتها، وتاريخ ورقم إصدار النظام ومخطط الجداول وأعدادها وملخص الأرصدة. لا تشمل اتصال MySQL أو app_key أو SMTP أو كلمات التخزين الخاصة، ولا جلسات الدخول وروابط إعادة التعيين وحدود محاولات الدخول؛ هذه لا يجوز نقلها كجلسات حية. حالة النجاح اليدوي تعني أن الخادم جهّز التنزيل، لا أنه يستطيع التأكد من حفظ جهازك له.

## الاستعادة إلى استضافة جديدة أو استبدال بيانات

1. ارفع **نفس إصدار النظام** على الاستضافة الجديدة، أنشئ الجداول، واضبط config.php لاتصال MySQL الجديد وHTTPS، ثم أنشئ مديرًا مؤقتًا من المُثبّت. لا تستورد إعدادات اتصال الاستضافة القديمة.
2. افتح القسم، اختر النسخة المشفرة وملف المفتاح المنفصل، واضغط «فحص النسخة ومعاينتها». تُعرض الوجهة والإصدار والتاريخ والأعداد الحالية والمستعادة وملخص المبالغ. لا تتغير البيانات عند المعاينة.
3. إذا كان في الوجهة بيانات، يلزم «تحميل نسخة كاملة» حديثة منها أولًا. احتفظ بها ومفتاحها قبل الاستبدال. حدد الإقرار واكتب «استبدال البيانات»، ثم أكد. أي تغير في بيانات الوجهة يبطل المعاينة ويطلب مراجعتها ثانية. صلاحية المعاينة10 دقائق وهي مرتبطة بالحساب والملف والقاعدة.
4. تتم الاستعادة داخل معاملة SQL واحدة، دون DROP/TRUNCATE أو تعطيل العلاقات. فشل قيد أو سجل يرجع كامل المعاملة. بعد النجاح تُبطل الجلسات القديمة ويظل المُثبّت مقفلًا؛ سجل الدخول بحساب مدير النسخة المستعادة. إعداد اتصال الاستضافة الجديدة وسياسة نسخها لا يتبدلان.

ملف النسخة والمفتاح يعالجان مؤقتًا من رفع PHP ولا يُنسخان إلى htdocs. حد النسخ الافتراضي16MiB قبل الضغط، ويتقيد أيضًا بذاكرة PHP (ثمن memory_limit) وبحد20000 صف لكل جدول. لا ينتج النظام نسخة جزئية عند تجاوز الحد. ارفع حدود PHP ورفع الملف وفق موارد الخادم، أو استخدم SQL من phpMyAdmin للقواعد الكبيرة. تظهر حدود الرفع في القسم. لا تختبر الاستعادة على قاعدة العمل الحقيقية دون نسخ آمنة ومراجعة.

## البريد والحفظ خارج الاستضافة

اضبط `backup` في config.php الخاص خارج htdocs:

```php
'backup' => [
  'hosting_profile' => 'unknown', // infinityfree أو cron فقط وفق الاستضافة الفعلية
  'max_plain_bytes' => 16777216,
  'max_attachment_bytes' => 5242880,
  'smtp' => [
    'host'=>'SMTP_HOST', 'port'=>587, 'encryption'=>'tls',
    'username'=>'SMTP_USER', 'password'=>'SMTP_APP_PASSWORD', 'from'=>'YOUR_VERIFIED_SENDER'
  ],
  'webdav' => [
    'url'=>'https://OTHER-STORAGE-HOST/PRIVATE-EXISTING-FOLDER',
    'username'=>'STORAGE_USER', 'password'=>'STORAGE_APP_PASSWORD'
  ],
],
```

استخدم مجلد WebDAV **خاصًا موجودًا بالفعل على خادم آخر**، لا نفس استضافة العيادة. لا حاجة لربط المشروع بمزود معين؛ أي مزود يدعم WebDAV الخاص وHTTPS صالح بعد الاختبار. كلمات الدخول لا توضع في الرابط أو JavaScript أو GitHub. TLS والتحقق من الشهادات إلزاميان، ولا يتبع الكود التحويلات. PHPMailer7.1.1 مرفقة مع رخصتها للإرسال عبر SMTP؛ لا تحتاج Composer على الاستضافة.

في القسم احفظ بريدك، ثم «اختبار الإرسال والوصول». يرفع النظام الملف المشفر، يعيد قراءته ويطابق SHA-256، ثم يتحقق أن الطلب دون تسجيل دخول يُرفض401/403. لا يعتبر التخزين العام نجاحًا. يرسل المرفق إن كان ضمن الحد، وإلا يرسل رابط HTTPS خاصًا يتطلب **حساب التخزين نفسه**؛ ليس رابطًا عامًا أو رابطًا يحتوي كلمة السر، ولا نفترض أنه رابط موقّع تنتهي صلاحيته. كل نسخة ناجحة تُحفظ خارج الاستضافة حتى عند إرسالها كمرفق. الملف المشفر فقط يذهب للمزود، لا مفتاحه الخاص.

أدخل رمز الوصول الموجود في البريد خلال30 دقيقة. قبول SMTP للرسالة وحده ليس تأكيد وصولها، ولهذا لا يُعتمد تفعيل الجدولة قبل الرمز. «نسخ وإرسال الآن» يعمل يدويًا بعد الإعداد ولا يحتاج cron. راقب سعة التخزين والاحتفاظ بالنسخ من حساب المزود؛ الكود لا يحذف نسخًا قديمة تلقائيًا.

## الجدولة والتحقق منها

- **InfinityFree المجانية:** cron معطل، والطلبات الآلية الخارجية لا تُعد بديلًا مضمونًا بسبب فحص المتصفح. اضبط hosting_profile إلى infinityfree؛ سيظهر أنها غير مدعومة ويبقى التنزيل والإرسال اليدوي متاحين. لا نستعمل الصفحة المفتوحة كجدولة. SMTP خارجي مناسب بدل PHP mail() المقيدة. [قيود cron](https://forum.infinityfree.com/t/cron-job-feature-is-now-disabled/80495)، [فحص المتصفح](https://forum.infinityfree.com/t/browser-security-system-features-and-limitations/49353)، [إرشادات SMTP الرسمية](https://forum.infinityfree.com/t/emails-from-my-website-arent-working/49242).
- **استضافة تدعم cron وPHP CLI:** بعد التأكد من اللوحة اضبط hosting_profile إلى cron. ضع نسخة backup-cron.php من الحزمة الخاصة خارج جذر الموقع، واضبط مهمة كل ساعة، مثل:

```text
0 * * * * /usr/local/bin/php /home/ACCOUNT/private-tools/backup-cron.php /home/ACCOUNT/clinic-private/config.php /home/ACCOUNT/public_html/api
```

عدّل المسارات وبنري PHP وفق الاستضافة، ولا تضف كلمات السر للأمر. فعّل «طلب النسخ الأسبوعي» في القسم. السكربت CLI فقط ولا يقبل Webhook عامًا. يرصد تشغيلين متباعدين دقيقة على الأقل وبحد3 ساعات بينهما؛ بعدها، مع اختبار البريد والتخزين، يظهر مفعّلًا. يرسل نسخة إذا مضت7 أيام على آخر إرسال ناجح، وتاريخها مرتبط بآخر نجاح لا بيوم أسبوع ثابت. افتح سجل cron في لوحة الاستضافة للتأكد أنه تشغيل مجدول بالفعل، وليس مجرد تشغيل يدوي للسكربت.

توقف رصد المهمة3 ساعات أو تغيير الاستضافة/الاتصال/إعداد النقل أو فشل الإرسال يلغي عرض «مفعّل». يظهر الفشل داخل القسم وتنبيه للمدير في شريط الموقع، ويحاول النظام إرسال رسالة فشل إن كان SMTP يعمل. إذا تعطل SMTP نفسه لا يمكن ضمان وصول إشعار بريد؛ يلزم مراقبة خارجية من لوحة المزود للضمان الإضافي. فتح الموقع يقرأ الحالة فقط ولا ينفذ النسخة المجدولة.

## ما اختُبر وحدود التفعيل

اختبار محلي بقاعدتي MySQL منفصلتين وبيانات مصطنعة: تطابق كل الجداول المنقولة والمرفقات وبصماتها والأرصدة، الحسابات والتجزئات، إبطال الجلسات، منع نسخة تالفة/مفتاح خاطئ/إصدار مختلف/معاينة قديمة، وrollback عند كسر علاقة. اختبارات الرفع والتنزيل والمعاينة والصلاحيات وCSRF عبر HTTP أيضًا. مسارات البريد والمخزن والجدولة جُربت بناقلات اختبار معزولة، لا برسالة حقيقية أو خدمة cron حقيقية.

المتاح حاليًا على اللاب لا يثبت قدرات الاستضافة الحية. ما لم تزود اسم/رابط الاستضافة وتضبط SMTP ومخزنًا خارجيًا وتختبر الوصول وcron عليها، تظل حالة النسخ الأسبوعي **غير مفعل**. لم تُرسل بيانات حقيقية خارج الجهاز ولم تُضبط حسابات خدمات أو فوترة تلقائيًا.
